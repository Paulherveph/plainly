# Plainly：用第二语言读懂各种文件

## 问题

一份法语租约、一封居留许可通知、一份满是条款的录用通知。当文件是你读得慢的语言时，风险在于漏看的内容：九天后要交的押金、不提前三个月书面通知就会自动续期的租约、没注意到的竞业限制。翻译工具能给出字面意思，却不会告诉你该做什么、什么时候之前做。

Plainly 读取一份文件，给出简明摘要、关键信息、带日期的待办事项、需要注意的条款，以及只根据这份文件回答问题的对话。无论原文是什么语言，都可以选择用英文、法文或中文解释。

## 约束

- **隐私。** 用户上传的文件可能包含住址、薪资或居留身份。文件存放在私有存储中，受行级安全保护，只能通过 60 秒有效的签名链接打开，30 天后自动删除，也可以一键立即删除。文件内容不会写入日志。
- **成本。** 访客无需注册即可试用，因此必须限制用量：每个文件最大 10 MB、20 页，访客每天 5 次分析，注册用户 20 次，同一文件同一语言的分析只做一次并缓存。
- **可信度。** 编造截止日期的模型比没有工具更糟。每一条结论都必须可以核对。

## 关键决策

1. **由 Claude 直接阅读原始文件。** 没有 OCR 流程，也没有向量数据库。PDF 或照片原样交给模型，页面文本只用于核对引文。
2. **引文核对决定显示什么。** 每条信息、待办和提醒都附带原文引文。应用会在忽略空格、大小写和换行连字符后，到页面文本中查找这句引文。找不到就删除该结论，并在页面上说明。对话遵循同样的规则：没有经过核对的引文，就不给答案。
3. **端口与适配器。** 用例依赖接口。每个 AI 端口都有一个 Claude 适配器和一个确定性的模拟实现，所以整个应用（包括 CI 中的端到端测试）都可以离线、免费运行。
4. **访客优先。** 访客第一次打开应用时会获得一个匿名账户，之后用 Google 或邮箱链接登录时，文件都会保留。

## 结果

- 66 个单元和用例测试，24 条数据库断言证明用户无法读取或修改他人的数据，19 个桌面和移动端的端到端测试。
- 10 份三种语言的评测文件。在确定性基线上，98% 的结论通过引文核对，没有出现文件未写明的日期。真实模型的分数：_首次用 API 密钥运行后补充_。
- 移动端 Lighthouse：无障碍 100，最佳实践 100，性能 93 到 96，实测 LCP 约半秒。
